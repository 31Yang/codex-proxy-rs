# v3.28.0

## 新增与改进

- 请求记录统一展示，支持成功、错误和全部状态筛选；失败、未完成及执行中的请求可按状态查找，重试中的错误不改变请求最终分类
- 请求历史保留期支持设置为 1～31 天，过期明细分批清理，相关统计由后台异步更新
- 账号分组支持控制生图权限，覆盖 Images 生成、编辑及 Responses 原生生图工具；Client Key 任一绑定分组禁止生图时统一拒绝，普通图片输入不受影响
- 诊断包改为后端收集与下载，包含已存错误原因、上游错误、尝试、时间线和恢复关联，并标明缺失或截断的证据；补齐内嵌认证头与令牌字段的脱敏
- 插件可通过公开服务维护用量明细、聚合统计并试算 Token 费用；调度插件支持过滤候选后委托内置调度，过滤约束同时应用于重选与等待

## 修复与调整

- 修复 OpenAI 在仅收到响应元数据后提前失去重试机会的问题，尚未产生实际输出时保留符合既有安全边界的重试
- 初始账号并发上限调整为 5，已保存的运行设置与账号独立并发配置保持原值
- 移除自动回切配置，保留智能调度系数、会话亲和与原生续写约束
- 调整隐私规则操作控件与插件目录空状态展示

## 升级说明

- 从已发布的 v3.27.1 升级时执行 `0032_usage_and_scheduling.sql`，包含历史保留期、表命名、分组生图权限与调度设置调整；已发布迁移保持原样。源码部署若已执行本轮旧的 0032～0035 迁移，需先核对迁移历史，不能直接套用该升级路径
- 保留期超过 31 天的已有设置会收敛到 31 天，过期请求随后由清理任务删除；需要保留的数据请提前备份。Client Key 结算账本不受请求历史清理影响
- 调度插件合同升级为 `scheduler` v2，已有 v1 调度插件需适配后使用；插件写入的聚合统计由写入方负责清理，不随插件卸载或请求历史保留任务删除
- 诊断包格式为 `schemaVersion: 5`，读取诊断包的脚本需适配新版结构；分享前仍应检查其中的业务内容与内部信息
