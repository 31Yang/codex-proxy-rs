# v3.26.0

## 新增与调整

- 移除「最小请求间隔」及其前后端、调度、数据库和插件设置字段；同一账号不再因上次请求开始时间而等待，并发、排队、额度与冷却限制继续生效
- 使用记录的首字耗时和总耗时按固定阈值分档着色，便于识别慢请求，不改变请求成功或失败状态
- 管理端请求和后端观测操作的默认保护时限调整为 120 秒，分别支持前端构建变量 `VITE_API_TIMEOUT_MS` 与部署配置 `store.pool.observability_timeout_seconds`；模型请求期限仍独立控制

## 修复与改进

- 优化大规模请求历史下的统计、账号与 Key 用量、精确分页和额度预测，复用数据库聚合与时间分段查询，移除固定十万行拒绝条件；保留精确总数、金额及未知值语义，并及时修正尚未投影的修改和删除
- 修复同一额度窗口内上游额度使用比例回落时预测累计量被错误重置的问题，保留已确认的历史用量
- 管理端导入 OpenAI 多账号 JSON 文件时逐账号处理、分别记录结果，自动按条目数和请求体大小分批；单个账号失败不再影响整份文件，已知过期且没有刷新令牌的账号会明确拒绝导入
- 优化 Codex 隐私规则对长请求的处理，减少重复复制、序列化和上下文遍历；取消固定 100 毫秒墙钟限制，保留大小、执行步数与请求取消检查，以及规则失败时的回滚语义
- 保留租约丢失、续期超时、升级会话结束和备份清理的真实失败原因；S3 连接测试在探针删除失败时报告失败，文件交换回滚失败时保留主错误及恢复路径
- 调整隐私策略文案与规则弹窗按钮，优化模型价格表的行高及单位提示
- 更新 `quinn-proto`，修复相关依赖安全问题

## 升级事项

- 新增 `0030_analytics_and_scheduling.sql`，创建统计索引、安排时间桶重建并删除请求间隔字段；保留已有统计事实和已完成的历史投影进度。升级前备份数据库，大数据量下索引创建会增加启动时间、磁盘占用与 I/O，迁移完成后服务才开始监听
- 已发布的 `0001–0029` 迁移保持不变，可从 `v3.25.0` 正常升级。若源码部署已执行本轮 `main` 中合并前的 `0030–0032`，不能直接沿用该迁移历史升级，需单独处理开发库数据；不要修改 `_sqlx_migrations` 的校验值绕过检查
- 管理 API 和插件设置不再提供 `requestIntervalMs`／`request_interval_ms`，依赖该字段的自定义调用方需同步调整
- 使用记录搜索仅按密钥、账号和模型做前缀匹配，密钥与账号名称使用历史快照；请求 ID 和上游 ID 改用对应精确筛选参数。搜索不再改变顶部统计范围，汇总、洞察和诊断不接受搜索参数，管理观测接口不再接受路由分组筛选
- 分组费用按当前组成员的请求费用汇总，调整成员关系后，留存窗口内的费用随当前成员重新计算
